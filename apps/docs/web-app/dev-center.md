# Dev Center

The Dev Center is available only to authorised developer accounts. Open **Dev Center** from the app menu. Other accounts cannot access its workspaces or developer API actions.

## Find the right workspace

| Task | Workspace |
| --- | --- |
| Review a request to close an account | Deletion requests |
| Continue an account conversation | User messages |
| Reply to a bug report or suggestion | Feedback tickets |
| Draft, preview or publish a product update | Changelog |
| Check provider connectivity | Service health |
| Investigate failed API requests or response times | API activity |
| Find an account and review its access or usage | Users |
| Review restricted account access | Bans & restrictions |

The sidebar highlights the current workspace. On a small screen, expand **Navigate** to switch tools. Every workspace has its own address, so bookmarks and the browser Back button work normally. **Back to Sky Style** returns to the product dashboard.

## Support and accounts

Deletion requests can be searched and filtered by status. Read the request, add an optional note, then approve or decline it. Approval records a decision; account deletion is a separate operation.

Open a conversation from a deletion request or use **Users → Open conversation** for another account. Feedback tickets are separate from these messages. Failed message requests retain the reply draft; refresh the conversation before retrying an uncertain send.

Account changes and exports are audited. Review the account identity and the operation's confirmation before changing access or deleting data.

## Publishing and monitoring

Use the Changelog editor's preview to check the public result. A successful save is read back before the editor clears. If verification fails, the draft stays available; refresh before retrying to avoid an accidental duplicate.

Service health shows provider reachability, measurement times and cached results. Refresh does not bypass the probe cache or generate an AI outfit. Use **API activity** for individual request failures; an operational health response does not guarantee every request succeeds.
